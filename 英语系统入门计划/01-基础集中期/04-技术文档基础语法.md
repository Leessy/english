# 技术文档基础语法

> 本文不按传统语法章节排列，而按技术文档中反复出现的功能组织：说明事实、给出操作、定义概念、声明要求、说明条件、描述结果和压缩信息。

## 模式 1：祈使句——步骤和命令

```text
(被省略的 You) + 动词原形 + 对象 + 位置/方式
```

| 例句 | 解析 | 中译 |
|---|---|---|
| Open the configuration file. | Open 原形；you 被省略 | 打开配置文件。 |
| Set the timeout to 30 seconds. | set A to B | 将超时时间设为30秒。 |
| Do not share the private key. | 否定祈使；do not + 原形 | 不要共享私钥。 |
| To continue, select Next. | 目的在前，指令在后 | 要继续，请选择“下一步”。 |

**识别点**：句首是原形动词，不代表它没有主语；主语是读者 you，只是没写出来。

## 模式 2：一般现在时——产品和 API 的稳定行为

| 例句 | 主语 | 为什么用现在时 | 中译 |
|---|---|---|---|
| The server returns a JSON response. | server（单数） | 描述固定行为 | 服务器返回 JSON 响应。 |
| This option disables logging. | option（单数） | 说明选项功能 | 该选项会禁用日志记录。 |
| Clients send requests over HTTPS. | clients（复数） | 说明协议行为 | 客户端通过 HTTPS 发送请求。 |
| The command does not modify the file. | command（单数） | 说明稳定的否定行为 | 该命令不会修改文件。 |

API 摘要中常看到省略主语的三单片段：`Creates...`、`Gets...`、`Lists...`、`Returns...`。它们的隐含主语是当前方法、端点或函数。

## 模式 3：系动词 + 表语——状态、性质和分类

| 结构 | 例句 | 中译 |
|---|---|---|
| be + adj. | The value is invalid. | 该值无效。 |
| be + noun | A token is a string. | token 是一个字符串。 |
| be + prep. phrase | The key is in the file. | 密钥在文件中。 |
| remain + adj. | The connection remains active. | 连接仍保持活动状态。 |
| become + adj. | The token becomes invalid. | token 会变得无效。 |

## 模式 4：被动语态——对象和结果比执行者更重要

```text
主动：The application loads the file.
被动：The file is loaded by the application.
常见文档式：The file is loaded at startup.  （不说谁加载）
```

| 时间/要求 | 被动结构 | 例子 |
|---|---|---|
| 一般现在 | am/is/are + done | The value is stored in memory. |
| 一般过去 | was/were + done | The file was deleted. |
| 现在完成 | has/have been + done | The issue has been fixed. |
| 情态要求 | modal + be + done | The key must be protected. |

**判断技巧**：看到 be + done，先译为“被/已……”，再按中文习惯调整。

## 模式 5：要求等级——不是所有“应该”都一样

| 等级 | 词 | 技术含义 | 例子 | 中译 |
|---:|---|---|---|---|
| 1 强制 | MUST / required / have to | 不满足就不符合规范/无法运行 | The ID must be unique. | ID 必须唯一。 |
| 1 禁止 | MUST NOT / prohibited | 绝对不允许 | You must not expose the key. | 不得暴露密钥。 |
| 2 推荐 | SHOULD / recommended | 通常应做，特殊情况可例外 | You should validate the input. | 建议验证输入。 |
| 2 不推荐 | SHOULD NOT / not recommended | 通常不应做 | You should not store passwords here. | 不建议在此存储密码。 |
| 3 可选 | MAY / optional / can | 可以做，也可以不做 | You may omit this field. | 可以省略此字段。 |
| 不必 | need not / do not have to | 不是必须，不等于禁止 | You do not have to restart. | 不必重启。 |

## 模式 6：条件和触发——if / when / unless

| 信号 | 例子 | 逻辑 |
|---|---|---|
| if | If the test fails, check the log. | 失败是可能情况；发生后检查日志 |
| when | When the app starts, it reads the file. | 启动被视为正常触发点 |
| unless | Do not continue unless the test passes. | 测试不通过就不得继续 |
| if ... then | If the value is empty, then the method returns null. | then 可省；引出结果 |

技术文档常将条件放在指令前，让不符合条件的读者直接跳过：

`If you use Windows, run the following command.`

## 模式 7：目的、用途和方法

| 结构 | 功能 | 例子 | 中译 |
|---|---|---|---|
| to + 原形 | 目的 | Run the command to start the server. | 运行该命令以启动服务器。 |
| To + 原形, 祈使句 | 先说目标 | To stop the server, press Ctrl+C. | 要停止服务器，请按 Ctrl+C。 |
| for + 名词 | 用途/对象 | a tool for testing APIs | 用于测试 API 的工具 |
| for + doing | 用途 | This method is used for creating users. | 该方法用于创建用户。 |
| by + doing | 方法 | Fix the issue by updating the package. | 通过更新软件包修复问题。 |
| without + doing | 不执行某动作 | Update it without restarting the app. | 在不重启应用的情况下更新它。 |

> `be used to do` = 被用来做；`used to do` 若没有 be，可能是“过去常常做”。不要漏看 be。

## 模式 8：doing / done 修饰——被压缩的从句

| 压缩形式 | 展开形式 | 理解 |
|---|---|---|
| a running process | a process that is running | 正在运行的进程（主动/进行） |
| the calling function | the function that calls | 调用方函数（函数主动发起调用） |
| the selected item | the item that is selected | 选中的项（被动/结果） |
| data returned by the API | data that is returned by the API | API 返回的数据 |
| files stored in memory | files that are stored in memory | 存储在内存中的文件 |

**做题法**：不确定修饰关系时，在脑中补回 `that is/are`，看意思是否成立。

## 模式 9：定义和引用

| 模板 | 例子 | 中译 |
|---|---|---|
| X is Y. | A repository is a storage location for code. | repository 是存储代码的位置。 |
| X refers to Y. | In this guide, client refers to your application. | 在本指南中，client 指你的应用。 |
| X consists of A and B. | The response consists of a header and a body. | 响应由头部和正文组成。 |
| X contains Y. | The object contains three fields. | 该对象包含三个字段。 |
| X represents Y. | This value represents the current state. | 该值表示当前状态。 |
| X: Y | Timeout: the maximum wait time. | Timeout：最长等待时间。 |

## 模式 10：存在与形式主语

| 结构 | 例子 | 怎样读 |
|---|---|---|
| there is + 单数/不可数 | There is no default value. | 没有默认值。 |
| there are + 复数 | There are three required fields. | 有三个必填字段。 |
| It is + adj. + to do | It is safe to retry. | 重试是安全的。 |
| It is + adj. + that... | It is important that the key remains private. | 密钥保持私密很重要。 |

it 在后两句中不指代具体物体，而是占住主语位置；真正内容在 to do 或 that 从句。

## 模式 11：列表和平行结构

`The tool lets you create users, manage keys, and view logs.`

```text
lets you
  ├─ create users
  ├─ manage keys
  └─ view logs
```

三个动词共享 `lets you`，形式平行。技术文档中的列表也常省略重复部分：

```text
The API supports the following operations:
- Creating users
- Updating users
- Deleting users
```

每项都与 `supports` 相连，因此应按同一结构理解。

## 模式 12：注意、警告和引用

| 模板 | 功能 | 中译 |
|---|---|---|
| Note that X... | 补充重要事实 | 请注意 X…… |
| Make sure that X... | 要求在操作前确认 | 确保 X…… |
| Warning: X... | 高风险提醒 | 警告：X…… |
| For more information, see X. | 引向其他文档 | 有关更多信息，请参阅 X。 |
| For example, ... | 引入例子 | 例如，…… |
| By default, ... | 说明未配置时的行为 | 默认情况下，…… |

## 模式 13：常见错误消息

| 错误片段 | 完整理解 | 常见处理动作 |
|---|---|---|
| File not found | The file was not found. | Check the path. |
| Permission denied | Permission was denied. | Check your access rights. |
| Invalid value | The value is invalid. | Use a valid value. |
| Connection refused | The server refused the connection. | Check whether the server is running. |
| Request timed out | The request exceeded the time limit. | Retry the request. |
| Already exists | The item already exists. | Use a different name. |
| Required field missing | A required field is missing. | Add the field. |
| Not supported | The feature is not supported. | Use a supported option. |

## 模式 14：配置和默认行为

| 模板 | 例子 | 中译 |
|---|---|---|
| X defaults to Y. | The port defaults to 8080. | 端口默认为8080。 |
| If omitted, X... | If omitted, the value defaults to zero. | 如果省略，该值默认为0。 |
| X is enabled/disabled by default. | Logging is enabled by default. | 日志记录默认启用。 |
| Set X to Y. | Set `debug` to `true`. | 将 `debug` 设为 `true`。 |
| X takes effect after Y. | The change takes effect after restart. | 更改在重启后生效。 |

## 模式 15：功能生命周期

| 词 | 不要误解 | 准确理解 |
|---|---|---|
| available | 不只是“可以获得的” | 功能/资源可用 |
| supported | 受官方支持 | 官方预期它正常工作并可能提供支持 |
| deprecated | 不等于立即删除 | 已弃用，尚可能可用，但不应新增依赖 |
| removed | 已移除 | 当前版本不再提供 |
| experimental | 实验性 | 行为或接口可能变化 |
| stable | 稳定 | 接口预期保持兼容 |

## 综合解析

`If authentication is enabled, each request must include a token generated by the server. To create a token, run the following command. The token is valid for 24 hours and can be refreshed without restarting the service.`

1. `If authentication is enabled`：条件 + 被动/状态，如果已启用身份验证。
2. `each request must include`：每个请求 + 强制要求 + 包含。
3. `a token generated by the server`：服务器生成的 token，过去分词后置修饰。
4. `To create a token`：目的。
5. `run the following command`：祈使句。
6. `is valid for 24 hours`：系表状态 + 持续时间。
7. `can be refreshed`：可选/能力 + 被动。
8. `without restarting`：无需执行的动作。

中译：**如果已启用身份验证，每个请求都必须包含一个由服务器生成的 token。要创建 token，请运行以下命令。该 token 的有效期为24小时，且可在不重启服务的情况下刷新。**

## 本章通关测试

对下列每句说出：模式、完整动词组、执行者、要求/时间/语态、中文大意。

1. Select a supported region.
2. The method returns an empty list by default.
3. The value is required.
4. The request is rejected by the server.
5. The client must not reuse the token.
6. If the token expires, create a new one.
7. Use this command to remove the package.
8. Data stored in memory is lost when the process stops.
9. A hook is a function that runs after an event.
10. There are two optional parameters.
11. The API lets you create, update, and delete users.
12. Note that this feature is deprecated.
13. Connection refused.
14. If omitted, the timeout defaults to 30 seconds.
15. The feature may be enabled without restarting the app.

每句的模式必须判对；第一次错的句子要在24小时后使用同模式新句复测。

## 编写依据

- [Google Developer Documentation Style Guide: Active voice](https://developers.google.com/style/voice)：主动语态通常更清楚，但强调对象、弱化责任主体或无需说明执行者时可用被动。
- [Google: Present tense](https://developers.google.com/style/tense)：技术说明中的一般行为优先用现在时。
- [Google: Second person](https://developers.google.com/style/person)：直接称呼读者为 you，操作指令使用祈使语气。
- [Google: Procedures](https://developers.google.com/style/procedures)：步骤以祈使动词开始，每步优先表达一个动作，并保持平行结构。
- [Microsoft Style Guide: Verbs](https://learn.microsoft.com/en-us/style-guide/grammar/verbs)：大多数内容优先现在时和主动语态，指令使用祈使语气。
- [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119)：MUST/MUST NOT、SHOULD/SHOULD NOT、MAY/OPTIONAL 表示不同要求等级。
- [ASD-STE100 FAQ](https://www.asd-ste100.org/STE_faq.html)：可迁移的原则包括短句、一句一个主题、主动语态和术语一致。
